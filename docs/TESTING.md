# Ручные сценарии проверки

## Подготовка

1. Запустить backend:

```bash
npm run server
```

2. Запустить frontend:

```bash
npm run dev
```

3. Открыть приложение в браузере.

## Сценарий 1. Health check API

Шаги:

1. Открыть `GET /api/health`.

Ожидаемый результат:

- сервер отвечает статусом `200`;
- в ответе есть `"status": "ok"`.

## Сценарий 2. Вход администратором

Шаги:

1. На главной странице выбрать роль `Администратор`.
2. Ввести `admin@sport.local`.
3. Ввести пароль `sport2026`.
4. Нажать кнопку входа.

Ожидаемый результат:

- создается активная сессия;
- открывается кабинет администратора;
- страница `/admin` становится доступной.

## Сценарий 3. Регистрация спортсмена

Шаги:

1. На главной странице открыть блок регистрации.
2. Выбрать роль `Спортсмен`.
3. Заполнить ФИО, e-mail, телефон, экстренную связь и пароль.
4. Указать представителя, возраст, уровень и спортивный фокус.
5. Нажать `Создать аккаунт`.

Ожидаемый результат:

- аккаунт создается без перезагрузки страницы;
- пользователь автоматически авторизуется;
- в системе появляется новый участник;
- спортсмен может перейти к списку секций и записаться.

## Сценарий 4. Регистрация родителя

Шаги:

1. Выйти из текущего аккаунта.
2. В блоке регистрации выбрать роль `Родитель`.
3. Заполнить данные родителя.
4. Указать имя ребенка, возраст, уровень и направление подготовки.
5. Нажать `Создать аккаунт`.

Ожидаемый результат:

- создается аккаунт родителя;
- в БД создается ребенок-спортсмен;
- у родителя открывается доступ к данным привязанного ребенка.

## Сценарий 5. Запись в секцию

Шаги:

1. Войти как спортсмен или родитель.
2. Перейти в раздел `Секции`.
3. Выбрать секцию с доступными местами.
4. Нажать кнопку записи.

Ожидаемый результат:

- появляется уведомление об успешной записи;
- количество участников в секции увеличивается;
- запись сохраняется после обновления страницы.

## Сценарий 6. Перенос тренировки

Шаги:

1. Войти под `admin@sport.local` или `coach@sport.local`.
2. Перейти в раздел `Расписание`.
3. Изменить слот, например на `2026-04-03T18:00`.
4. Сохранить изменения.

Ожидаемый результат:

- расписание обновляется;
- при конфликте по залу или тренеру API возвращает ошибку;
- в интерфейсе показывается уведомление о результате.

## Сценарий 7. Изменение посещаемости

Шаги:

1. Войти под администратором или тренером.
2. Открыть раздел `Посещаемость`.
3. Изменить статус одного участника.

Ожидаемый результат:

- статус обновляется сразу в таблице;
- данные сохраняются через API;
- спортсмен и родитель видят только свои записи.

## Сценарий 8. Проверка достижений

Шаги:

1. Войти спортсменом или родителем.
2. Открыть раздел `Достижения`.

Ожидаемый результат:

- спортсмен видит только свои достижения;
- родитель видит достижения привязанного ребенка;
- без авторизации раздел недоступен.

## Сценарий 9. Защита маршрутов

Шаги:

1. Выйти из аккаунта.
2. Попробовать открыть `/attendance`, `/achievements`, `/admin`.
3. Войти спортсменом и открыть `/admin`.

Ожидаемый результат:

- без авторизации показывается сообщение о необходимости входа;
- спортсмен и родитель не получают доступ к `/admin`;
- администратор получает полный доступ к административной панели.
