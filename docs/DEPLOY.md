# Деплой проекта

## Вариант 1. Локальный production-запуск

1. Установить зависимости:

```bash
npm install
```

2. Собрать frontend:

```bash
npm run build
```

3. Запустить приложение:

```bash
npm start
```

После этого Express будет:

- обслуживать API по `/api/*`;
- раздавать собранный frontend из `dist/`;
- открывать SPA-маршруты через один сервер.

## Переменные окружения

Пример:

```env
PORT=3001
HOST=0.0.0.0
JWT_SECRET=change-me-in-production
```

Шаблон лежит в файле `.env.example`.

## Вариант 2. Deploy на Render

В репозитории уже добавлен файл `render.yaml`.

### Что сделать

1. Загрузить проект в GitHub.
2. Создать новый Web Service в Render.
3. Подключить репозиторий.
4. Убедиться, что Render использует:

- build command: `npm install && npm run build`
- start command: `npm start`

5. Задать переменную окружения `JWT_SECRET`.

### Что важно помнить

- база SQLite хранится в файле, поэтому на бесплатных облачных сервисах данные могут быть временными;
- для демонстрации курсовой этого обычно достаточно;
- для постоянного хранения лучше вынести базу в отдельное хранилище.

## Вариант 3. Deploy на Railway или аналогичный Node-hosting

Подходит тот же сценарий:

- build: `npm install && npm run build`
- start: `npm start`

## Проверка после деплоя

После публикации нужно проверить:

1. Открывается главная страница приложения.
2. Работает `GET /api/health`.
3. Выполняется вход в демо-аккаунт.
4. Открываются разделы `Секции` и `Расписание`.
5. Защищенные маршруты ограничены по ролям.
